# Konnect fork survey — 2026-10-31

Purpose: find which forks of the archived Konnect repository contain development work worth
merging into the owner's own fork, and measure how hard each merge is.

Method and raw data: `scripts/fork_survey.py` (lists every branch of every fork and asks the
GitHub compare API how many commits it is ahead of / behind upstream `main`), then the upstream
and Copperpour pull-request lists, then `git merge-tree --write-tree` test merges in a scratch
bare repository (no working tree, nothing built or executed).

## 1. Corrections to the starting assumptions

1. **The archived repository is `mixelpixx/Konnect`, not `marju212/Konnect`.**
   `mixelpixx/Konnect` was archived after 2026-10-25. Its README says development moved to
   *Konnect-EDA* (Orchis.ai LLC), which is **commercial, closed-source** software, free only during
   its beta. The open-source (AGPL-3.0) line therefore continues only through forks.
   `marju212/Konnect` is one of those forks. It is not archived; it had 5 new commits between
   2026-10-29 and 2026-10-31 and has no forks of its own.
2. **The GitHub account `qmlxml` has no Konnect fork yet.** "Merge into my own fork" first
   requires creating one, and the repository it is forked from fixes its GitHub fork network
   permanently (see section 5).

## 3. Copperpour — the community continuation

- `Copperpour/Copperpour`, created 2026-10-23, a GitHub fork of `mixelpixx/Konnect`, AGPL-3.0.
- Maintained by `pauliuszaleckas` (third-largest upstream contributor, 61 upstream commits,
  189 in Copperpour) and `mn89h` (Malte Nilges), with contributions from `davidtdab`, `dsandall`
  and others. Six forks of it are actively feeding pull requests back.
- **255 commits ahead of upstream `main`. It is behind by exactly 6 commits**, and those 6 are the
  README changes announcing the move to Konnect-EDA. Copperpour therefore contains all of
  upstream's code.
- Of the 20 pull requests from outside contributors still open on upstream at archive time,
  **19 are already merged into Copperpour** (matched by commit title). The one missing is
  `DylanRowe88` #741 (placement of footprints with custom-shape pads, 1 commit, based 111 commits
  behind upstream); it merges into Copperpour main with no conflict.
- Release v0.15.0 published 2026-10-28; 54 merged and 7 open pull requests in its own repository;
  139 open issues.
- **On 2026-10-29 Copperpour renamed every crate directory `crates/konnect-*` to
  `crates/copperpour-*`** (commit "refactor: rename the konnect\* crates to copperpour\*"). Any
  branch based on upstream that adds or edits files under the old names gets conflicts on top of
  Copperpour for that reason alone. Git places new files in the renamed directories correctly
  (shown as 0 conflict regions below); edited files need resolving.

## 6. Decision needed: the base of the owner's fork

See the question put to the owner in the session of 2026-10-31. Options measured above:

- **A. Fork `Copperpour/Copperpour`**, then merge the independent forks onto it. Cost: resolve the
  crate rename and the overlaps in section 4 (largest: `marju212`'s PCB sync).
- **B. Fork `mixelpixx/Konnect`**, merge the independent forks onto it (they merge with almost no
  conflicts). Cost: the 255 Copperpour commits, including the 19 absorbed upstream pull requests,
  are not included; adding them later means the same rename and overlap work as option A, on a
  larger and diverging base.
- **C. Fork `marju212/Konnect`.** Equivalent to B with marju212's 5 commits already in place.

`J3Techs`' native router is a separate decision (160 commits, 190 files, unreviewed by anyone
other than its author).

### Ruling (owner, 2026-10-31): option A

The owner chose **A, fork `Copperpour/Copperpour`**. Both reviewers consulted (the first and the
second) recommended A independently. The second reviewer's added advice: merge the forks with little code
overlap first (`yuvaltal912-sys`, `daGrumpf-bxp`, `AryanSenthil`, `halthinks`, `DylanRowe88`
#741); treat `marju212` as a per-behaviour comparison against Copperpour's own sync fixes, not
a line merge; offer merged work back to Copperpour as pull requests; keep `J3Techs` on a separate
branch until someone other than its author has reviewed it.

Done:
- Fork created: `qmlxml/Copperpour` (parent `Copperpour/Copperpour`).
- Local clone at the project directory. Remotes: `origin` (the fork), `copperpour`, `upstream`
  (`mixelpixx/Konnect`), and one remote per candidate fork, named after its owner.
- Branch layout: `main` is kept identical to `copperpour/main`, so syncing stays a fast-forward.
  Merged fork work and these notes are on the branch `integration`.
- SSH access to GitHub is not configured on this machine; remotes use HTTPS.
