# Konnect fork survey — 2026-10-31

Purpose: find which forks of the archived Konnect repository contain development work worth
merging into the owner's own fork, and measure how hard each merge is.

Method and raw data: `scripts/fork_survey.py` (lists every branch of every fork and asks the
GitHub compare API how many commits it is ahead of / behind upstream `main`), then the upstream
and Copperpour pull-request lists, then `git merge-tree --write-tree` test merges in a scratch
bare repository (no working tree, nothing built or executed).

## 1. Corrections to the starting assumptions

1. **The archived repository is `mixelpixx/Konnect`, not `marju212/Konnect`.**
   `mixelpixx/Konnect` was archived after 2026-10-25. Its README says development moved to
   *Konnect-EDA* (Orchis.ai LLC), which is **commercial, closed-source** software, free only during
   its beta. The open-source (AGPL-3.0) line therefore continues only through forks.
   `marju212/Konnect` is one of those forks. It is not archived; it had 5 new commits between
   2026-10-29 and 2026-10-31 and has no forks of its own.
2. **The GitHub account `qmlxml` has no Konnect fork yet.** "Merge into my own fork" first
   requires creating one, and the repository it is forked from fixes its GitHub fork network
   permanently (see section 5).

### Step 1 ruling (owner, 2026-10-31): `DylanRowe88` #741 is not merged

Commit 5ff2355 writes a custom-shape pad as a rectangle of the pad's `(size ...)`. In KiCad the
`(size ...)` of a custom pad is the anchor pad; the primitives may extend beyond it. Verified on
the KiCad library installed here: `Jumper.pretty/SolderJumper-2_P1.3mm_Open_RoundedPad1.0x1.5mm`
has anchor `(size 1 0.5)` and primitives spanning about 1.05 x 1.5 mm. The second opinion
found the same in `Package_DFN_QFN` exposed pads and `Mounting_Wuerth` pads, and counted 599 of
15,464 library footprints with custom pads. The commit would write undersized copper and report
success. Its test uses an invented footprint whose size equals its primitives' extent, so it
cannot detect this. Its stated precedent is also out of date: `crates/copperpour-ipc/src/client.rs`
now maps `roundrect` and `chamfered_rect` to their own KiCad shapes.

Copperpour's refusal (which names the footprint) is kept. Both models recommended this.

Recorded as deferred work: KiCad's typed IPC pad stack has `PssCustom` with `custom_shapes`
(`crates/copperpour-ipc/proto/board/board_types.proto:294`). Translating the footprint's
primitives into `custom_shapes` would place these footprints with correct copper. That is a
separate feature, not part of this merge plan.
