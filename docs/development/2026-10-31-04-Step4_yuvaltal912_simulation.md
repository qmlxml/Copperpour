# Step 4 — `yuvaltal912-sys/Konnect`: SPICE simulation through ngspice

Plan: `2026-10-31-00-Fork_Survey.md`, section 7. Design and evidence: `docs/SIMULATION_PLAN.md`;
traps and open items: `docs/SIMULATION_NOTES.md`; agent skill:
`crates/copperpour/assets/skills/kicad-simulation/SKILL.md`.

What the contribution adds: a `simulation` toolset with `check_simulation_readiness` and
`run_simulation`. A schematic is copied into a private folder, its SPICE netlist exported with
kicad-cli, the deck flattened and vetted (preflight), and run in a separate `copperpour sim-worker`
process that loads ngspice's shared library (`libngspice`, loaded at run time with `libloading`;
not linked). Operating point, transient analysis with measurements, and protection scenarios.
About 24,700 added lines, most of them tests and fixtures.

## Merge

29 of the fork's 31 commits cherry-picked with `-x`, author kept, in order. Left out:
- `53dab89` "tell agents about the local knowledge graph" and `dd3d5fa` "keep the local graph
  report out of the doc counts": both serve a tool (graphify) on the contributor's machine only.

Conflict resolution, repeated over many commits:
- Tool counts and the Konnect name in README.md, DEV.md, docs/TROUBLESHOOTING.md,
  plugin/plugin.json, packaging/metadata.json and tool-directory.md: Copperpour's side, by its rule
  that pull requests leave counts alone. Done with the new `scripts/keep_head_in_conflicts.py`,
  which keeps the contributor's changes that merged without conflict and prints what it drops.
  Afterwards every line the contributor added to those files was compared with what landed; the only
  real loss was the `simulation_failed` row of DEV.md's error table, restored by hand. The rest
  were counts and names.
- `AGENTS.md`: Copperpour's file kept. The contributor's version held instructions for their own
  coding agent (reply in Hebrew, paths on their Mac, their git address).
- `Cargo.lock`: Copperpour's file, then regenerated by one build without `--locked`, which added
  only the new dependencies (12 lines: `libloading`, `libc`).
- `crates/copperpour-core/src/tools/cli.rs`: the contributor's runner change taken over step 2b's.
  They give kicad-cli a null stdin (in stdio mode stdin is the MCP pipe) and kill it on timeout
  only when it runs on a private copy (`run_cli_owned`), because a kicad-cli killed on a live
  project leaves the project's lock file behind. Step 2b had set the kill for every call, which
  could leave such locks; the contributor's rule is better and was adopted.
- `crates/copperpour-sexp/src/writer.rs`: the contributor extracted a public `state_root()`;
  merged with Copperpour's lookup of `COPPERPOUR_STATE_DIR` before `KONNECT_STATE_DIR`.
- `docs/reliability-legacy-inventory.json`: both entries kept.
- The contributor's working-state document `docs/SIMULATION_HANDOFF.md` came in with the commits.

The cherry-picked commits keep the fork's crate names, so they do not compile on their own;
renaming inside each commit would have made every later commit conflict on the renamed lines.
The adaptation commit after them makes the result compile.

## Adaptation commit

- Moved the new directories git's rename detection did not move:
  `crates/konnect-core/src/simulation/` → `crates/copperpour-core/src/simulation/`, its fixtures,
  and the skill `kicad-simulation` → `crates/copperpour/assets/skills/`.
- Crate names (`konnect_core`, `konnect_sexp`, …) and paths in the new files; test fixture paths
  (`../konnect-core/tests/fixtures` would not have been found); the configuration directories the
  live tests plant (`.config/copperpour`, which Copperpour reads; `.config/konnect` would have
  tested nothing); `CARGO_BIN_EXE_copperpour`; `copperpour sim-worker`; "Konnect" →
  "Copperpour" in messages and comments of the new files.
- Kept on purpose: the deck title `.title konnect simulation` (it is inside the binary raw-file
  fixtures, which would otherwise no longer match) and the worker's internal status markers.
- Two Copperpour API changes since the fork's base: toolset metadata no longer has `tool_count`
  (counts come from the tool list), and `sha2` 0.11 digests no longer format as hex
  (`crate::hex::encode_hex` used instead).
- `docs/SIMULATION_HANDOFF.md` replaced by `docs/SIMULATION_NOTES.md`: the goal, file map,
  verification (adapted), traps and known open items kept; the sections about the fork's own pull
  requests, next steps and local tools removed.
- `run_drc_on_private_copy` added; the SES candidate check (step 2b) uses it, so it is still killed
  on timeout. Tests `a_timed_out_kicad_cli_is_killed` (private copy) and
  `a_timed_out_kicad_cli_on_a_live_project_is_not_killed` (states why not acting is correct and
  when it would be wrong).
- First gate run after the adaptation: 44 new test failures, from two causes.
  (a) Every test that starts a fake simulation worker or a fake kicad-cli failed with "Exec format
  error (os error 8)": the contributor's test scripts have no `#!` line, which Linux will not
  execute (they were written and run on macOS). Each of the two test modules now has a local
  `write_script` that adds `#!/bin/sh` when the body has none; no test body changed.
  (b) `no_file_quotes_a_stale_toolset_count`: the new toolset makes 22, and DEV.md,
  packaging/metadata.json and tool-directory.md said 21. Toolset counts (unlike tool counts) must be
  correct whenever a toolset is added; changed to 22 (and 11 categories in tool-directory.md).
  After both: the simulation unit tests (453) and the count test pass.
- Gate after the adaptation (`logs/gate-step4-adapt.summary`): 3,653 passed (+482), 1 failed (the
  known baseline failure), 108 ignored (+48, the simulation's live tests).
